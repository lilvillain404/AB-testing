# A/B testing project
[![Excel](https://img.shields.io/badge/Excel-000?style=for-the-badge&logo=microsoftexcel&logoColor=green)](https://www.microsoft.com/excel)

## 1. Определяем цель тестирования
Продуктовая команда заметила, что **часть пользователей не продлевает подписку** после первого списания. Сейчас отправляется стандартное уведомление о продлении. Разработка персонализированного письма (с напоминанием о просмотренном контенте) требует ресурсов разработки — команде нужно понять, оправдано ли это.

**Что тестируем:** не просто текст письма, а гипотезу о том, что напоминание о полученной пользе повышает воспринимаемую ценность сервиса.

**Цель теста:** подтвердить или опровергнуть, что персонализация уведомления повышает конверсию продления и лояльность пользователей.

## 2. Выбор метрики

Основная метрика — **конверсия продления**. 

Тип метрики определяет выбор статистического критерия: для конверсионных метрик — Z-тест для пропорций, для количественных — t-тест или бакетный тест, для ratio-метрик — дельта-метод.

## 3. Формулировка гипотезы

**Нулевая гипотеза (H₀):** Персонализированное email-уведомление не влияет на конверсию продления. Различия между группами A и B являются случайными.

**Альтернативная гипотеза (H₁):** Персонализированное email-уведомление с напоминанием о просмотренном контенте приводит к статистически значимому росту конверсии продления по сравнению со стандартным уведомлением.

## 4. Готовим эксперимент

* **Разбиение на группы.** Пользователи случайным образом делятся на контрольную (A, стандартное письмо) и тестовую (B, персонализированное письмо) группы в соотношении, близком к 50/50 — это обеспечивает однородность выборок.

* **Уровень значимости:** α = 0,05 — допускаем 5%-ю вероятность ложно обнаружить разницу, которой на самом деле нет.

Расчёт минимального размера выборки по историческим данным:
| Параметр | Значение |
|----------|----------|
| Базовая конверсия (p1) | 55% |
| MDE (минимально значимый эффект) | 8 п.п. |
| Целевая конверсия (p2) | 63% |
| Мощность | 80% |
| Уровень значимости (α) | 5% |
| **Необходимый размер выборки на группу** | **≈ 590 пользователей** |

* **Длительность теста** выбирается кратной неделе или месяцу, исходя из размера выборки и дневного потока подходящих пользователей.

## 5. Проводим эксперимент
Тест запускается только после проверки корректности сбора данных. Останавливать эксперимент досрочно можно только при резком критическом ухудшении метрики или обнаружении технических ошибок — «подглядывание» в промежуточные результаты. 

## 6. Проверяем валидность эксперимента

* **A/A-тест** — тот же тест на данных до запуска A/B, чтобы убедиться, что группы изначально однородны, а разница после теста связана именно с нововведением.

* **Проверка на SRM** (Sample Ratio Mismatch) — фактическое распределение пользователей по группам должно соответствовать запланированному; существенное отклонение может говорить об ошибке в механизме сплитования.

## 7. Анализ данных

| Параметр | Control (A) | Test (B) |
|----------|-------------|----------|
| **Конверсия** | 59,2% | 68,8% |
| **Наблюдений (n)** | 500 | 500 |

| Показатель | Значение |
|------------|----------|
| **Разница конверсий** | +9,6 п.п. |
| **Стандартная ошибка** | 0,030 |
| **Z-статистика** | 3,18 |
| **P-value** | 0,0015 |
| **95% доверительный интервал разницы** | [+3,7%; +15,5%] |

* **P-value** значительно ниже α = 0,05, а доверительный интервал не включает 0 — H₀ отклоняется в пользу H₁.
* **Guardrail-метрика:** не стало ли письмо навязчивым. Отдельной метрики удовлетворённости в данных нет, поэтому в качестве proxy взяты дни подписки — если персонализация раздражает, стоит ожидать, что пользователи начнут уходить быстрее. Разница средних проверена t-тестом в двух срезах:
  
| Срез | Среднее, A (дней) | Среднее, B (дней) | p-value (t-тест) |
|------|-------------------|-------------------|------------------|
| **Среди всех пользователей** | 326,7 | 351,3 | 0,016 |
| **Среди тех, кто не продлил** | 154,7 | 221,0 | 2,9×10⁻⁸ |



## 8. Итоги

Вот мы и подобрались к итогам данной работы. Стоит написать выводы и замечания.

* **Статистическое решение:** H₀ отклонена (p = 0,0015 < α = 0,05) — разница в конверсии не случайна.

* **Бизнес-результат:** конверсия выросла с 59,2% до 68,8% (абсолютный прирост +9,6 п.п., относительный +16,2%).


**💼 Рекомендации:**

- Внедрить персонализированное письмо для всех пользователей
- Обновить email-кампании продления на новый шаблон
- Задокументировать результат для будущих A/B-тестов

**Ограничения и что можно улучшить**
* **Фактическая выборка меньше расчётной.** По расчёту на входные параметры требовалось ≈590 пользователей на группу, по факту в тесте участвовало по 500. Таким образом тест недобрал мощность относительно исходного плана. Результат всё равно значим, но с более консервативным запасом.
* **Guardrail-метрика.** Дни подписки не были частью изначального дизайна теста — для честной проверки «навязчивости» стоило бы заранее заложить прямую метрику удовлетворённости (отписки от рассылки, жалобы, NPS) и её собственный размер выборки.
* **Данные синтетические**, использованы для отработки методологии, а не реальные данные компании.
